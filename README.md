# ATTENTION BANK

**Платформа добровольного измеримого взаимодействия: компании платят за подтверждённый результат, а не за случайный просмотр.**

Стартовая ниша: **Gaming & Digital Product Testing**. Студии и разработчики приложений получают проверенный фидбек, участники получают AB Points и тратят их на награды от этих же компаний.

```
Компания создаёт задачу → пользователь выполняет → Backend проверяет →
начисляются AB Points → пользователь получает уведомление (сайт + Telegram) → компания получает результат
```

## Быстрый запуск (1 минута)

Нужен только **Node.js 22.13 или новее**: https://nodejs.org. Устанавливать пакеты (`npm install`) не нужно, у проекта нет зависимостей.

```bash
cd attention-bank
npm start
```

Откройте **http://localhost:3000**

| Роль | Email | Пароль |
|---|---|---|
| Участник | `demo@attention.bank` | `demo1234` |
| Компания (студия) | `studio@attention.bank` | `demo1234` |
| Компания (приложение) | `apps@attention.bank` | `demo1234` |

На странице входа есть кнопки демо-доступа.

На Windows можно просто дважды кликнуть `start-windows.bat`.

Другие команды:

```bash
npm test       # автотесты всего цикла (9 сценариев, включая Telegram и безопасность)
npm run seed   # сбросить базу и заново заполнить демо-данными
npm run dev    # запуск из исходников (server/) с автоперезагрузкой
npm run build  # пересобрать attention-bank.mjs после изменения кода (нужен esbuild: npm i -D esbuild)
```

### Как устроен запуск

`npm start` запускает **один файл `attention-bank.mjs`**. В нём собраны сервер, сайт, бот и схема базы. Для работы (и для Render) достаточно двух файлов: **`package.json` + `attention-bank.mjs`**. Исходный код для чтения и правок лежит в папках `server/` и `public/`. После изменений в них выполните `npm run build`.

## Что реально работает

**Участник (Web + PWA)**
- регистрация (16+, согласие на обработку данных), вход, профиль;
- выбор интересов, по ним подбираются задания;
- список заданий, страница задания, кнопка «Начать задание» (сервер фиксирует время начала);
- ответы трёх типов: оценка 1–5, текст, выбор варианта; есть счётчик символов;
- отправка результата, затем автопроверка и решение компании;
- кошелёк: баланс и **журнал транзакций** (`+50 Game Feedback Completed`, `−80 Награда Redeemed`), сверка баланса с журналом;
- магазин наград (ключи раннего доступа, скины, премиум), выдача кода;
- уведомления на сайте, которые обновляются сами каждые 10 секунд;
- установка на телефон как приложение (PWA).

**Компания (Business Dashboard)**
- **Create Campaign**: название, описание, категория, награда, количество участников, вопросы, аудитория. Кнопка **Publish**, после неё задание сразу появляется у участников;
- живой расчёт бюджета: награда + комиссия, резерв, сумма в ₸;
- очередь проверки: ответы, оценка качества 0–100, флаги автопроверки, репутация участника. Кнопки «Одобрить» и «Отклонить»;
- агрегированные результаты (графики оценок и выборов, цитаты), экспорт в CSV;
- пауза и закрытие кампании, неиспользованный бюджет возвращается;
- создание своих наград для участников.

**Telegram-бот**
- привязка аккаунта: код на сайте, затем `/start КОД` в боте. Это верификация: **1 Telegram = 1 аккаунт**;
- уведомление после одобрения:
  ```
  🎉 +50 AB Points
  Your task was approved.
  New balance: 150 AB
  ```
- команды `/balance`, `/history`, `/tasks`, `/unlink`;
- публикация новых заданий в **Telegram-группу или канал**;
- компании приходит уведомление о новом результате на проверку.

## Подключение Telegram (5 минут)

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot`, получите **токен**.
2. Скопируйте `.env.example` в `.env` и заполните:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   TELEGRAM_BOT_USERNAME=attention_bank_bot
   ```
3. *(Необязательно)* для публикации заданий в группу: добавьте бота в группу или канал администратором и укажите `TELEGRAM_GROUP_ID`. ID группы можно узнать через @userinfobot или @getidsbot (у групп он начинается с `-100`).
4. Перезапустите `npm start`. В консоли появится `[telegram] бот @... запущен (polling)`.
5. На сайте: **Профиль → Подключить Telegram → Открыть бота**. Страница сама обновится после подтверждения.

Режим `polling` работает даже на ноутбуке без публичного адреса. Для сервера с HTTPS можно включить `TELEGRAM_MODE=webhook` и указать `PUBLIC_URL`. Запросы без секретного заголовка Telegram отклоняются.

Без токена сайт работает полностью, а Telegram-сообщения печатаются в консоль сервера.

## Сценарий демо для защиты (3–4 минуты)

Откройте **два окна**: обычное и инкогнито.

1. **Окно 1: компания** `studio@attention.bank`. Создать → заполнить кампанию → смотрим, как считается бюджет → **Опубликовать**. В Telegram-группе появляется пост «Новое задание».
2. **Окно 2: участник** `demo@attention.bank`. Новое задание уже в списке → **Начать задание** → ответить → **Отправить результат**. Показываем штамп «НА ПРОВЕРКЕ» и оценку качества.
3. **Окно 1**: в кампании открыть «На проверке» → видны оценка качества, флаги, репутация → **Одобрить**.
4. **Окно 2** через несколько секунд сам показывает **«ПОДТВЕРЖДЕНО +50 AB»**, баланс растёт. **В Telegram приходит «🎉 +50 AB Points».**
5. **Кошелёк**: журнал транзакций и плашка «Баланс совпадает с журналом». Объясняем, что баланс меняет только сервер.
6. **Награды**: обменять AB на ключ раннего доступа → в журнале появляется `−80 Redeemed`.
7. *(Если спросят про накрутку)*: в кампании «Плейтест Steppe Runner» → «На проверке» лежит ответ «норм норм норм…». У него флаги «Выполнено слишком быстро» и «Формальный текст» и низкая оценка качества.

### Защита начисления баллов

```
User completes task → Server validates → Server creates transaction → Database updates balance
```

- Клиент **не может** изменить баланс. `PUT /api/me` игнорирует поля `balance` и `role` (проверено тестом).
- Любое изменение баланса проходит через `postTransaction()` в `server/services/ledger.js`. Запись в `transactions` и обновление баланса делаются в **одной атомарной транзакции БД**.
- Баланс не может уйти в минус (`CHECK (balance >= 0)` и проверка в коде).
- Сверка: `баланс == SUM(transactions)`. Она показана в кошельке и в `/api/health`.
- Одобрить результат можно только один раз. Повторное одобрение блокируется статусом.
- Бюджет компании резервируется заранее, поэтому награду невозможно выплатить «из воздуха».

### Автопроверка (Backend проверяет)

| Проверка | Что ловит |
|---|---|
| Время от «Начать» до «Отправить» | ответы «не глядя» |
| Повторы слов, мало уникальных символов | «норм норм норм», «ааааа» |
| Совпадение текста с другими участниками | копирование ответов |
| Одинаковые оценки во всех вопросах | ответы «на автомате» |
| Telegram-верификация | мультиаккаунты (1 Telegram = 1 аккаунт) |
| История отклонений | недобросовестные участники |
| Одно участие на кампанию, лимит заданий в сутки | фарм баллов |

Если оценка ниже 30, ответ отклоняется автоматически. Если оценка 70 и выше и у кампании включено автоодобрение, ответ одобряется сразу. Всё остальное проверяет компания.

### Экономика (иллюстративная модель MVP)

- Цена результата для компании = награда участнику + комиссия платформы (по умолчанию 20%, задаётся в `.env`).
- При публикации резервируется `(награда + комиссия) × участников`.
- Деньги списываются **только за одобренные результаты**. Отклонённый ответ освобождает место, а при закрытии кампании остаток возвращается.
- Проценты — иллюстративная модель. Их нужно подтвердить расчётами на реальных кампаниях.
- Пополнение бюджета в MVP работает в демо-режиме (`/api/company/deposit`). В продакшене здесь будет платёжный шлюз.

## Ответы на вопросы жюри

**Чем вы отличаетесь от reward-платформ?** Мы продаём подтверждённый результат, а не действие. Компания платит только за ответ, прошедший автопроверку и её собственное одобрение. Неиспользованный бюджет возвращается. У каждого ответа есть оценка качества и репутация автора.

**Почему компания выберет вас?** Маленькой студии трудно быстро найти 20 живых тестировщиков из целевой аудитории. Здесь это одна форма и бюджет от нескольких тысяч тенге, а оплата только за проверенный фидбек. Результаты собраны в графики и CSV.

**Откуда первые компании и пользователи?** Начинаем с одной ниши: инди-студии, разработчики приложений и студенческие стартапы (хакатоны, IT-сообщества, геймдев-чаты). Первые участники — геймеры и tech-аудитория из Telegram-сообществ. Telegram-группа с новыми заданиями работает как канал привлечения.

**Почему AB Points имеют ценность?** Награды дают сами студии: ключи раннего доступа, внутриигровые предметы, премиум-подписки, имя в титрах. Для геймера это ценно, а для студии почти бесплатно и ещё и вовлекает.

**Что если начнут накручивать?** Смотрите таблицу автопроверки выше. Плюс одно участие на кампанию, суточный лимит, 1 Telegram = 1 аккаунт и решение компании перед выплатой.

**Данные и возраст?** Регистрация с 16 лет и согласием на обработку данных. Компания видит ответы и имя, но не email и не контакты.

## Деплой

Подойдёт любой хостинг с Node.js 22+ (Render, Railway, VPS). Команда запуска: `npm start`. В корне репозитория обязательно должны быть `package.json` и `attention-bank.mjs`, остальные файлы для запуска не нужны.

**Render:** New → Web Service → репозиторий. Build Command: `npm install`, Start Command: `npm start`, тип Free. Переменные окружения: `NODE_VERSION=22`, `PUBLIC_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_MODE=webhook`, `TELEGRAM_WEBHOOK_SECRET`, при необходимости `TELEGRAM_GROUP_ID`. ID группы можно узнать командой `/chatid` в группе. Укажите `PUBLIC_URL=https://ваш-домен` (нужен для кнопок в Telegram и защищённых cookie). Для постоянного хранения данных подключите диск под `DB_PATH` или перенесите схему на PostgreSQL (`db/schema.postgres.sql`).
